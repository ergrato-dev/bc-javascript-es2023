# 🌐 Webgrafía - Semana 23

## Referencia

1. [performance.now()](https://developer.mozilla.org/es/docs/Web/API/Performance/now) - MDN (español). El reloj para medir y por qué los navegadores reducen su precisión.
2. [User timing](https://developer.mozilla.org/en-US/docs/Web/API/Performance_API/User_timing) - MDN (inglés). `mark`, `measure` y cómo leer las entradas.
3. [Intersection Observer API](https://developer.mozilla.org/es/docs/Web/API/Intersection_Observer_API) - MDN (español). Opciones (`root`, `rootMargin`, `threshold`) y las entradas que recibe la función.
4. [Window.requestAnimationFrame()](https://developer.mozilla.org/es/docs/Web/API/Window/requestAnimationFrame) - MDN (español). Ejecutar código antes del siguiente fotograma.
5. [Debounce](https://developer.mozilla.org/en-US/docs/Glossary/Debounce) y [Throttle](https://developer.mozilla.org/en-US/docs/Glossary/Throttle) - MDN (inglés). Las dos definiciones, en el glosario.
6. [Gestión de memoria](https://developer.mozilla.org/es/docs/Web/JavaScript/Guide/Memory_management) - MDN (español). El ciclo de vida de la memoria, el recolector y las estructuras débiles.
7. [Performance measurement APIs](https://nodejs.org/api/perf_hooks.html) - Node.js (inglés). La API `performance` de Node, la que usan los labs 01 y 04.

## Guías

1. [Lazy loading](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading) - MDN (inglés). `loading="lazy"`, `import()` y otras formas de cargar más tarde. Repaso de la teoría 03.
2. [Avoid large, complex layouts and layout thrashing](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing) - web.dev (inglés). Las fases del pintado y por qué leer medidas después de escribir es caro. Repaso del lab 03.
3. [Optimize long tasks](https://web.dev/articles/optimize-long-tasks) - web.dev (inglés). Qué es una tarea larga y cómo partirla. Repaso del paso 6 del lab 03.
4. [Interaction to Next Paint (INP)](https://web.dev/articles/inp) - web.dev (inglés). La medida de lo que tarda una página en responder.
5. [Analyze runtime performance](https://developer.chrome.com/docs/devtools/performance) - Chrome for Developers (inglés). Grabar y leer la pestaña Performance de las DevTools.
6. [Fix memory problems](https://developer.chrome.com/docs/devtools/memory-problems) - Chrome for Developers (inglés). Heap snapshots, nodos desconectados y el Performance monitor. Repaso de la teoría 04.
